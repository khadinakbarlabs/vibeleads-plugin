# VibeLeads 0.2.0 product upgrade

Improve useful decisions and continuity, rather than promising a measured tenfold performance gain. Keep one skills-only package with user-owned data access, owned-first Actors, explicit fallback and no bundled service, agent personas, sender, scheduler or telemetry.

1. Add business-context, adaptive-prospecting, feedback-learning, session-continuity, scheduled-prospecting and lead-reporting workflows. Shared state uses readable, user-selected workspace files outside the installed plugin; host memory is optional, not assumed.
2. Give the lead engine a short context/research/decision/results/learning loop. Research available business context before asking; distinguish observations from hypotheses. Use narrow pilots, confidence and cost-aware next actions; retain uncertainty and exact-source restrictions.
3. Store deliberate feedback as explicit preferences or attributed outcomes, not model training. Preserve negative/suppression examples; avoid overfitting tiny biased samples. User preferences never become spend, outreach or scheduling authority.
4. Define recurring-work contracts, host capability checks, shared budgets, deduplication, half-open time windows, partial-run recovery, meaningful-change alerts and pause/expiry rules. Do not activate any real schedule in this development task.
5. Test an optional offline report generator before implementation. Reuse the quality engine to derive counts and evidence, preserve distinct grains and suppression, compare sessions honestly, render accessible responsive HTML plus Markdown/JSON, escape untrusted content, make no network requests and protect source files.
6. Independently review realistic behavior and implementation, exercise native Claude loading, visually inspect a fictional report, validate all package/platform schemas, build/extract both archives, and record actual limitations.

Success is a useful first session with minimal questioning, a second session that reuses context without stale authorization, a meaningful feedback change, a resumable partial monitor, and a report whose metrics come from actual inputs. Real collection, host schedule execution, conversion lift and marketplace approval need separate evidence.
