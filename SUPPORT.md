# Support and troubleshooting

First identify the skill and host, whether the task is planning/import/live collection, and the safe error category. Read the connection guide for missing tools, expired authentication, schema changes, minimum-charge rejection and partial/empty results.

For a bug report include package version, host version, skill name, sanitized reproduction input and expected vs observed behavior. Do not include API keys, credential files, private lead lists, raw metadata/build payloads or customer data. A fixture using fictional companies is preferred.

The public repository support destination has not been established for this local candidate. Until publication, review issues with the package maintainer in the current workspace. Do not advertise a guessed support URL.
